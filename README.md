# 走行後主観評価アプリ（Subjective Survey Webapp）

> **本アプリは回答データを一切送信せず、端末内（localStorage）にのみ保存します。**
> 外部リソース（CDN・Webフォント・アナリティクス等）の読み込みも一切行いません。
> データの回収は「CSV書き出し → iPadのファイルApp → USB」の手動運用です。（倫理説明用）

ドライビングシミュレータ実験において、各走行（セット）終了後に参加者がiPadで回答する主観評価アプリです。

実験1・実験2の2つの流れを持ち、セットアップ画面の「実験」で選びます（設定は `config.js` の `experiments`）。

| | 実験1 | 実験2 |
|---|---|---|
| 条件 | セットアップで1つ選び、全走行で固定 | 全員が条件Cを2回 → A・Bを2回ずつ。セットアップで順序（C→A→B / C→B→A）を選ぶと、走行番号から条件が自動で決まる |
| 予定走行数 | 既定8（変更可） | 6（順序から決まるので変更不可） |
| 追加走行 | できる | できない（7走行目の条件が無いため） |
| 質問（提示順） | 主体感 → パフォーマンス →（A・Bのみ）予測可能性 → RSME | 主体感 → 原因 → 否定 → パフォーマンス →（A・Bのみ）予測可能性 → RSME |

各質問：

1. **行為主体感（JoA, `joa`）** — 7段階リッカート
2. **原因（`cause`、実験2のみ）** — 減速は自分の操作が引き起こしたか。7段階リッカート
3. **否定的な項目（`neg`、実験2のみ）** — ひとりでに減速したか。7段階リッカート
4. **主観的運転パフォーマンス（`perf`）** — 7段階リッカート
5. **支援システムの予測可能性（`pred1`〜`pred3`、3項目・同一画面）** — 7段階リッカート。**条件A・Bのみ**（Cでは出さず、CSVは空欄）。2・3項目めは逆転項目（画面には表示しない。CSVは素点のまま）
6. **メンタルエフォート（RSME, `rsme`）** — 0–150の縦型ビジュアルアナログ尺度

実験2の文言（「できた／していた」「減速／速度の変化」）は未確定で、代替案を `config.js` のコメントに残しています。
実験2だけ文言を変えるときは `experiments.exp2.questions` に上書きを書きます（実験1の文言は変わりません）。

## 構成

```
/index.html      画面（セットアップ／回答／確認／待機／完了／実験者パネル）。1問1画面のリッカートは app.js が config.js から生成
/style.css       スタイル（システムフォントのみ）
/app.js          ロジック（保存・CSV書き出し・消去の安全機構）
/config.js       質問文・RSMEアンカー定義・バージョン番号（文言変更はここだけ）
/sw.js           service worker（全アセットをキャッシュ、オフライン動作）
/manifest.json   PWAマニフェスト
/icons/          アイコン
/package.json    npm run dev（手元確認用。本番の配布には関係しない）
/scripts/dev-server.mjs  依存パッケージなしの開発用静的サーバ
```

## 0. 手元で確認する

```sh
npm run dev
```

`http://localhost:5173/` を開く（ポートは `PORT=8080 npm run dev` で変えられる）。依存パッケージは無いので `npm install` は不要です。
同じWi-FiのiPadからは、起動時に表示される `LAN` のURLで開けます（httpなのでservice workerは動きません）。

- localhostではservice workerを登録しません（キャッシュ優先のため、編集が反映されなくなる）。オフライン動作を手元で試すときは `http://localhost:5173/?sw=1` で開く
- サーバは `Cache-Control: no-store` で返すので、編集後は再読み込みだけで反映されます

質問文やRSMEアンカーの変更は `config.js` の編集のみで完結します（`app.js` に文言はありません）。
なお `config.js` の `RSME_ANCHORS` は仮訳です。**大門・土屋(2017)日本語版の確認後に差し替えてください**（★要確認コメント参照）。

## 1. GitHub Pages デプロイ手順

1. このリポジトリをGitHubへpush
2. リポジトリの **Settings → Pages** を開く
3. **Source** で「Deploy from a branch」を選び、ブランチ（例 `main`）とフォルダ（`/ (root)`）を指定して **Save**
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

※ 非公開リポジトリでPagesを使う場合はGitHub Pro等が必要（GitHub Student Developer Pack申請後に非公開化を推奨）。

## 2. iPad側セットアップ

1. SafariでデプロイされたURLを開く
2. 共有ボタン → **「ホーム画面に追加」**
3. 以後は**ホーム画面のアイコンから起動**する（スタンドアロン起動）
4. 初回に一度オンラインで開けば全アセットがキャッシュされ、以後は**機内モードでも完全動作**する

## 3. 実験運用手順

### 実験前

1. ホーム画面アイコンからアプリを起動
2. セットアップ画面で **参加者ID**（例 P01）と **実験** を選ぶ
   - 実験1：**条件**（A/B/C）・開始走行番号・予定走行数を入力
   - 実験2：**条件の順序**（C→A→B / C→B→A）と開始走行番号を入力（各走行の条件は順序の下に表示される）
3. 「回答を開始」をタップ（以後、実験と条件・順序はセッション中ロックされる）
   - 次の走行の条件は実験者パネルの上部に出る（参加者の画面には出さない）

### 各走行後

1. iPadを参加者に渡す
2. 参加者が回答（上の表の提示順 → 確認 → 確定）
3. 「保存しました」の表示と待機画面を確認してiPadを回収
4. 次の走行後は、待機画面の小さな「次の回答へ」ボタン（実験者操作）で次の回答を開始

予定走行数の回答が終わると完了画面が表示されます。追加走行が必要な場合は「追加の走行を回答する」で継続できます。

### 実験後（データ回収）

1. **画面右下隅の薄い丸ボタンを1.5秒長押し**して実験者パネルを開く
2. 「この参加者のみCSV書き出し」を実行（参加者ごとに1回・1ファイル。全走行分が行として含まれる）
3. 保存ダイアログでファイルAppに保存 → ファイルAppからUSBへコピー
4. コピーを確認してから「書き出し済みデータを消去」を実行
   （未書き出しレコードが1件でも残っていると消去ボタンは押せません）
5. 「セッション終了」でセットアップ画面に戻る

### CSV仕様

- 「この参加者のみ」は、セッション中の実験の記録だけを書き出す
  - 実験1：`timestamp,participant,condition,run,joa,perf,pred1,pred2,pred3,rsme,app_version`（v1.x と同じ）／ファイル名 `survey_{participantID}_{YYYYMMDD}.csv`
  - 実験2：`timestamp,participant,condition,run,joa,cause,neg,perf,pred1,pred2,pred3,rsme,app_version`／ファイル名 `survey_exp2_{participantID}_{YYYYMMDD}.csv`
- 「全件」は、実験が1種類ならその列。2種類混ざっていれば `participant` の前に `experiment`（`exp1`/`exp2`）列が入り、回答列は両方の和集合（無い項目は空欄）
- 条件Cの `pred1`〜`pred3` は空欄
- `pred2`・`pred3` は逆転項目。CSVは素点のままなので、分析時に `8 − 値` で反転する
- 全件書き出しのファイル名：`survey_all_{YYYYMMDD}.csv`（実験2だけなら `survey_exp2_all_{YYYYMMDD}.csv`）

## 4. 注意事項

- **localStorageはSafariの長期未使用時に消去されうるため、実験当日中に必ずCSVを書き出すこと**
- 同一「実験×参加者ID×走行番号」の記録が既にある場合は警告が出ます（実験1と実験2で同じIDを使っても衝突しない）（上書きは明示確認後のみ）
- 実験者パネルから直前レコードの削除（誤記録時）が可能です
- 初回ロード後のネットワーク通信が0件であることは、Safariの開発者ツール（Mac接続）のNetworkタブで確認できます
